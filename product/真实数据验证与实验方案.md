# 真实数据验证与实验方案

## 首要产品问题

新用户在首次 7 天内完成个性化训练计划，是否会增加第 4 周仍持续训练的人数？

“AI Coach 使用者留存更高”可能受到自选择影响：本来就更有训练意愿的用户更容易使用 AI Coach，也更容易留存。

## 数据接入

关键表包括 users、events、workouts、subscriptions 和 experiments。数据质量门槛：主键唯一；所有事件统一为 UTC；注册、计划创建、训练开始和完成形成可审计事件链；渠道归因窗口、退款窗口和留存口径在分析前冻结；机器人、内部账号、重复安装和测试账号有明确排除规则。

## 观察性分析

先构建注册 cohort，比较完成计划与未完成计划的 D7/D28 训练留存。使用匹配、分层或回归控制渠道、国家、设备、注册日、训练经验和首日活跃度。观察性结果只用于估计实验价值和识别异质性，不能单独证明因果。

## 随机实验

| 项目 | 定义 |
|---|---|
| 人群 | 满足条件的新注册用户 |
| 分组 | 用户级随机，避免同一用户跨版本 |
| 对照 | 当前 onboarding |
| 实验 | 明确 AI Coach 入口 + 引导式创建首个计划 |
| 主指标 | D28 有效训练留存 |
| 护栏 | 退款率、卸载/通知关闭、支持工单、onboarding 完成率 |
| 诊断 | 计划创建、首次训练完成、首周训练天数 |
| 周期 | 覆盖完整 D28 观察窗，提前计算样本量 |
| 分析 | Intent-to-treat；预先写明排除项和停止规则 |

## 渠道预算判断

渠道比较应使用贡献利润或预测 LTV/CAC，并保证统一归因窗口。Influencer、Paid Ads 和 Organic 的用户结构不同，不能用合成数据中的付费率直接调整预算。必要时按市场或渠道进行增量实验。

## 对现有仓库结论的改写规则

- “提升 20%”改为“在合成数据中相关，需实验验证”。
- “建议加大渠道预算”改为“建议先核验归因与增量贡献”。
- “入口太深导致低使用率”改为“可能解释之一，需可用性研究或实验验证”。
- 所有目标值应来自真实基线、样本量和单位经济模型，不从行业均值直接推导。

## 上线后的决策输出

实验结束后只回答三个问题：主指标是否达到预设最小可检测效应；护栏指标是否在可接受范围；结果是否在关键市场、渠道和设备上方向一致。只有三项都满足，才进入扩大流量或长期上线决策。
